# Public README — Operational Hub

This package is a **hatch checklist + Operational Hub skeleton**. It is **not** a one-click AI Campus, and it is **not** a Building starter.

## Beta

This starter is a **beta / betta-test** public release. Expect rough edges. The primary success path is the chatbot / paste path below. Optional Mac `.command` helpers and First Run installer templates (if offered later) are optional beta helpers — not required.

## Chatbot / paste path

Load this starter by pointing an AI at the files **or** dragging them into a chatbot (ChatGPT, Google AI / Gemini, and similar).

Many chatbots cannot upload a whole folder. If folder upload fails, **drag files in batches** (or paste one file at a time, starting with `START HERE.md`). Ship content for that path is **markdown / text only**. Obsidian `.json` configs under `.obsidian/` may be present and are optional. You do not need images, audio, or a `.command` file to succeed.

The AI’s first visible reply should print the © / use notice (see `USE NOTICE.md`), then continue warmly.

## First run

1. **Download** the starter zip and unzip it.
2. **If the chat can take a folder:** drop the unzipped folder and say **Start Here** or **go**.
3. **If the chat can only take one file (free Gemini and similar):** paste `START HERE.md` first, then say **Start Here** or **go**. The guide will ask for the next file by name.

The AI’s first reply should be the copyright / use notice, even when `START HERE.md` is the only file it has. `README.md`, `GO.md`, and `USE NOTICE.md` all carry that same notice.

After setup, the guide can put the installer in `Operational Hub/40 Archive/First run/` and leave a daily `START HERE.md` so the next **go** boots a helper seat. You can start over from that archive, or from a fresh zip.

The AI becomes your Startup guide and walks the rest with you — no Terminal, no Mac-only steps required. Details live in package-root `START HERE.md`. If these `.md` files are new to you, see `How to open these notes.md`. This release was written in Obsidian (free for personal use, not required). If you later want a double-click starter for your computer, the guide can give you one file from `launcher-templates/`. This zip does not include runnable `.command` or `.bat` files.

## What this is

The **Operational Hub** is the life-level organization vault. Capture, projects, next actions, review rhythm, and dual Core seats live here. **Domains** are specialized areas of life or work; in AI Campus teaching language they are often shown as **Buildings**. Buildings hang off Areas of Life that this hub tracks — they are a separate package, not this one.

## What you get

- Empty floors: Inbox, Projects, Areas & Contexts, Resources, Archive, Someday-Maybe, Daily, JournalEntries, Calendar
- Dual Core seats on hatch: **Operations Secretary** (capture / process / review) and **Vault Architect** (structure / harness)
- Office furniture shells, Mail Room stubs, Conference Room stubs, Core SOP procedures (sanitized)
- Templates with Owner naming (no personal credentials)
- Optional launcher templates in `launcher-templates/` — offered by the Startup guide if you want a file for your computer; not required

## What this is not

- Not a finished multi-Building AI Campus
- Not the Building starter (that is a separate package for domain vaults)
- Not a product that silently runs email or calendar for you
- **Not branded as GTD.** Getting Things Done (David Allen) is a major influence among many personal organization methods. Vault language here stays Hub / floors / next actions / review.
- Not a requirement to use AI. Markdown is the store of record. You can run the whole Hub with a text editor and no model.

## How to use

1. Prefer the **First run** path above (download → drop into chat → Start Here / go). See `START HERE.md`.
2. Read [[HONEST_LIMITS]]
3. Follow [[How to Hatch the Operational Hub]] when you want the fuller checklist
4. Replace placeholders and fill Role/Persona shells
5. Later, boot each seat from `Operational Hub/Main Lobby/Start Here.md` (seat boot — different from package-root first-run)
6. Hatch Buildings separately when an Area of Life needs its own stacked office

## Honesty

A hatch is multi-step. Obsidian is recommended; any Markdown folder works. Personas are shells you fill. Review rhythm is your job — that is the product.
