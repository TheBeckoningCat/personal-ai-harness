[[Conference Room/README|Conference Room]] explains the room. The Work Table directory contains the Table Topics currently under discussion. This file explains how to manage them.

A **Table Topic** is a Markdown file currently being discussed on the Work Table. Owner approved this term on 2026-08-17.

## What Goes Where

- **Work Table** contains the Table Topics being discussed now. Keep approximately one to four active topics.
- **The Docket** contains proposed Table Topics that have not entered discussion. It does not contain finished discussions.

the Owner's Must Dos remain in Daily, [[70 Strategy & Operations/Projects.base|Projects Base]], or `10 Projects`. Do not move project notes into the Conference Room. A Table Topic may link to a project, but it is not another copy of the project.

## How We Talk Here

Follow [[70 Strategy & Operations/Conference Room/How We Talk]] and [[Main Lobby/Campus Communication Standard]]. Use complete sentences and preserve each person's individual voice. Do not use status fragments, manufactured slogans, or unexplained shorthand.

Owner is not required to follow the same writing standard. Writing costs him more, and Campus staff should not correct his grammar or ask him to match their response length.

Outside the Conference Room, follow the communication standard appropriate to the document. One-to-one Mail Box notes created from `[WITH Operations Secretary]` or `[WITH Vault Architect]` Next Actions use the same complete conversational style as the Conference Room. See [[Communications Board Standard]].

When Owner says **update the SOP**, update every current instruction needed to make the approved behavior consistent. This may include the authoritative procedure, office startup instructions, templates, and the README people follow.

## Review The Work Table

Owner may ask: `Do a pass of the Work Table.` This means to complete the review below.

**Operations Secretary and Vault Architect**

1. Open the Work Table directory. Each Markdown file there is an active Table Topic.
2. Check every footer first. If Owner marked Finished and selected File or Delete, Operations Secretary processes that choice during this review. She does not ask him to repeat the instruction or alter his checkboxes.
3. Read the newest Talk comments on each remaining topic. Answer comments addressed to you or `@All` and place each new response at the top of Talk with the writer's name and date. Do not rewrite another person's words.
4. This review is not a full startup procedure.

**Operations Secretary also**

1. Review The Docket first. Move a proposed topic onto the Work Table only when Owner names it for discussion.
2. Review the footers, then read each active Table Topic. If Owner also requested GTD processing, scan `10 Projects` for Planned Actions marked `NEXT` and move them according to [[Project Action Layers]].
3. For Finished and Delete, delete the Table Topic. For Finished and File, move the same file to `30 Resources/Table Topics (Ref)/`. Do not leave a second copy or an obsolete pointer, and do not move finished discussions to The Docket.
4. Notify the Message Board when an `@All` request still needs another person's response.

**Vault Architect does not** process Daily, Inbox, or GTD project filing.

## Table Topic Format

```markdown
# Name

**Project:** [[10 Projects/Name]]
*(or: none - ad hoc)*

One or two sentences explaining the question or purpose. New discussion belongs under Talk.

## Talk
*(newest first; include the writer and date; do not rewrite another person's words)*

## Lessons
*(repeatable lessons, usually recorded when the topic closes)*

## Footer
Owner marks the result, then asks Operations Secretary to process it.

- [ ] Finished
- [ ] File
- [ ] Delete
```

Use `Templates/Table Topic.md` for a new topic. Add `Templates/Snippet - Footer.md` only when an older topic lacks the footer.

Owner marks Finished first and then selects either File or Delete. Delete is the default because the approved result should already be recorded in the project, procedure, or reference note connected to the discussion.

File means to move the same Table Topic to `30 Resources/Table Topics (Ref)/`. Add `table talk` and the date to the filename when that label is missing. Do not leave a second copy or a pointer at the former location.

## Completion

- **Finished and Delete:** Operations Secretary deletes the Table Topic.
- **Finished and File:** Operations Secretary moves the same Table Topic to `30 Resources/Table Topics (Ref)/`.
- Finished topics do not move to The Docket or the Public Filing Cabinet.
