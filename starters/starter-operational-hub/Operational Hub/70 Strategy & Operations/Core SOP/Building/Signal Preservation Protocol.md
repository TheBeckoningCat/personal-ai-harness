# Signal Preservation Protocol

This procedure protects meaning in the Owner's free-form notes when an agent summarizes them, removes uncertainty, or rewrites work that requires stronger judgment.

## Core Rule

Raw Capture is the original record. A summary helps a reader understand or locate that record but does not replace it.

## the Owner's Intent (2026-08-03)
Signal preservation is **not** an excuse to delay processing.

Operations Secretary should still:
- process, prioritize, create/update projects, and consolidate ramblings efficiently;

while also:
- keeping important decisions, numbers, names, dates, emotional or strategic details, and useful wording inside or linked from the project note;
- when a note moves to Resources or Archive, **take the rich content with it** (or keep a clear link) so later reuse is possible;
- supporting Operations Secretary across model hosts by recording durable information in the vault rather than leaving it only in chat.

Preserve enough detail to verify important conclusions without making the active project hard to read. Prefer a concise project note with a short “Sources and important details” section over either an unsupported summary or an unorganized collection of source material.

## Information Types
1. **Raw Capture** - Daily notes, Inbox, pasted handoffs, journal entries, screenshots, and rambling notes. Preserve unless Owner explicitly says to delete.
2. **Clean Filing** - project notes, references, calendar items, waiting-for lists, and next actions derived from raw capture.
3. **Overview** - short lists used for navigation and review.
4. **Archive or Closeout** - a concise record of completed work that retains links to its sources.

## Rules Based On Model Capability
- A general or less capable model may file information, add links, mark checkboxes, identify Calendar items, and add short processing notes. It should not rewrite detailed summaries, mission notes, or high-stakes references unless Owner asks.
- A model capable of reliable synthesis may consolidate, compare, and rewrite, but it must preserve source links, unresolved questions, and important nuance.
- Any model should retain a detail and identify the uncertainty when it cannot determine whether the detail matters.

## Compression Rules
- Summarize by extracting decisions, next actions, waiting-fors, dates, people, and durable context.
- Preserve proper nouns, dates, amounts, locations, and quoted user phrasing when it carries meaning.
- Do not replace a rich note with a generic conclusion.
- If a summary is interpretive, label it as the Operations Secretary's interpretation.
- If medical, legal, financial, or current-software information is involved, mark unverified claims clearly.

## Before Big Capture Days
- Create or identify the raw capture location first (usually Daily `## Capture` or `00 Inbox`).
- Do not process while Owner is still recording raw Capture unless he asks.
- After Capture is complete, first file the material, then summarize it when needed, and finally create or update projects.
- On the Daily Note, evidence of handling is **`## Processed`** (strike-through original + short disposition) per [[Daily Note Standard]] — not large routing tables. Operator detail stays in [[Offices/Operations Secretary/Scratch Pad]].

## Verification Checklist
- Did I preserve the raw source?
- Did I link the source from the filed note?
- Did I avoid changing high-signal content unnecessarily?
- Did I distinguish fact, user memory, and AI interpretation?
- Did I leave open questions instead of guessing?
