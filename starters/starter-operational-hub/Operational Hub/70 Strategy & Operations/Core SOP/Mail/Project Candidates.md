# Project Candidates

**Status:** #status/active · approved 2026-08-20  
**Architect:** Vault Architect · **Operator:** Operations Secretary  
**Director packet:** Town Hall `Mail Room/Packet Kit/Project Candidate.md`

A **Project Candidate** reports a possible or accepted commitment created through work in another Building that GTD may not yet record. It is not an official GTD project until Operations Secretary processes it. Specialists report candidates to their Director within the Building. The Director sends the consequence to Operations Secretary through Town Hall. Building staff do not edit `10 Projects`.

## When A Director Sends One

Send a Project Candidate during the Building's closing procedure, or sooner when Owner asks, if the work produced a possible multi-step outcome or a commitment Owner accepted.

An accepted commitment exists when Owner clearly said that he will start, buy, schedule, ask, practice, pursue, or otherwise continue something.

When it is unclear whether Owner accepted a recommendation, ask him when practical. A recommendation may still be sent, but its status must be **Pending candidate**. Use **Accepted commitment** only when Owner accepted it.

Do not send a Project Candidate merely because the Building inspected information or discussed an idea. Combine related consequences from one discussion into a single packet. Do not copy an existing GTD project into the packet.

A Director normally cannot inspect GTD and is not responsible for finding duplicate GTD records. Send an accepted consequence once unless the Director already has the Operations Secretary's acknowledgment identifying the same unchanged consequence and its official GTD location. When the Director knows of a possible existing project, name it as a possible merge location. Operations Secretary verifies the official record and removes duplication.

No packet is required when the Building produced no pending or accepted consequence for GTD, or when Operations Secretary already acknowledged the same unchanged consequence.

## Minimum Packet

```text
Type: Project Candidate
Building / Director:
Status: Pending candidate / Accepted commitment
Outcome or decision:
the Owner's words:
As-of time or deadline, if relevant:
Authorized local source:
Question or blocker, if any:
```

Do not attach a routine Session Update merely because the work session ended. Case files, charts, research, specialist reasoning, and local work history remain in the Building.

## What Operations Secretary Does

1. Copy the packet from Town Hall into `Mail Room/Mail Boxes/Operations Secretary`. Verify that the local copy opens and is complete, then delete the Town Hall transfer copy.
2. Preserve the Owner's meaning and wording. Do not turn the commitment into a slogan.
3. Search active projects and the relevant Someday-Maybe notes for the same outcome.
4. Choose one disposition:
   - **New project:** The outcome can be completed independently and no active project already covers it.
   - **Merge:** An active project has the same outcome. Add the new actions or facts there without creating another project.
   - **Planned or Next Action:** The consequence belongs in an existing project's action lists. Move a line to Next Actions only when Owner selected it.
   - **Recurring:** The consequence is an ongoing practice. Add it to the existing record for that practice or ask Owner where it belongs.
   - **Someday-Maybe:** Owner did not accept it as active work. Owner determines this status.
   - **Reference:** The information is useful but creates no open commitment.
   - **No commitment:** The packet creates no GTD work. Do not alter the Building's local files.
5. Maintain one official GTD project for each outcome. The Building keeps its local case files and working material.
6. When one packet contains outcomes that can be completed or abandoned independently, file them separately and link them when useful.
7. Ask Owner when the packet does not contain enough information to determine the GTD result. Do not invent the outcome.
8. When one outcome involves more than one Building, keep one official GTD project and identify one lead Director. Other Buildings may contribute without creating competing GTD records.
9. File the processed packet under `Mail Room/Public Filing Cabinet/Operations Secretary/From <Director>/`. Send the Director a short Town Hall acknowledgment that identifies the disposition, official GTD location, and any remaining question or action.

## Action Selection

Owner may select more than one current action when several can proceed together. Move every action he explicitly selected into Next Actions. Keep a Director's unaccepted proposal in Planned Actions or ask Owner. See [[Projects/Project Action Layers]].

## Return Acknowledgment

```text
Project Candidate received: <title>
Disposition: <new / merged / planned / next / recurring / someday / reference / no commitment / question>
Official GTD home: <project or other note>
What remains in your Building: <local working material>
Next action or question: <one line or none>
```

The acknowledgment tells the Director whether and where GTD recorded the consequence.

## Do Not

- Allow a Director to edit `10 Projects`.
- Allow a specialist to bypass the Building Director for ordinary commitment mail.
- Assume that a consequence was recorded when no acknowledgment identifies its official GTD location.
- Create another GTD project merely because the Building has a local case or campaign.
