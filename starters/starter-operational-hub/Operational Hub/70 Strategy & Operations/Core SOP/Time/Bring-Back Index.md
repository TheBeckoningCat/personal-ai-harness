# Bring-Back Index

**Status:** #status/active · approved by Owner 2026-08-12  
**Architect:** Vault Architect  
**File:** [[Calendar/Bring-Back Index]]

Bring-Back is not a to-do list, a project-review queue, or another Inbox. Its former GTD name was “tickler file,” which this system no longer uses.

## Purpose

Bring an item back to the Owner's attention on a date that Owner selected or explicitly approved.

## Who May Add An Item

| Person | Authority |
|---|---|
| **Owner** | May always add an item and date. This is the preferred method. |
| **Operations Secretary** | May add an item only when Owner directs a date or approves a date Operations Secretary proposed. |
| **Vault Architect and other collaborators** | May propose an item and date. They write the Index only when Owner explicitly asks them to do so. |

When Owner has not selected or approved a date, do not add the item to Bring-Back.

## Appropriate Uses

1. **Future reconsideration:** The matter should not receive attention until a particular date.
2. **Recurring review:** A project or routine should return for attention on an approved schedule.

Examples:

- `2027-01-15 - Start planning Camlin/Aaron visit if still likely. Source: [[Camlin and Aaron Japan Visit 2027]]`
- `2026-09-15 #monthly - Computer backup check. Source: [[Vault Backup and Archive Strategy]]`
- `remind:: 2026-11-01 Review FEHB decision space`

## Use Another GTD Location When

| Situation | Correct location |
|---|---|
| The action can be done now | Project **Next Actions**, with a Context when useful |
| It is a future project action without a date for renewed attention | Project **Planned Actions** |
| It depends on another person or event | Project **Waiting For** |
| It must happen at a specific date, time, or place | [[Calendar/Calendar]] |
| Owner may want to consider it someday but has set no date | Project, Daily Capture, or `50 Someday-Maybe` |
| Owner must decide but has set no date | Project note or Daily **Needs My Decision** |
| The action already exists in a project | Leave it in the project rather than recording it twice |

## Sections In The Index

| Section | Purpose |
|---|---|
| **Due today** | Items dated today |
| **Coming soon** | Items dated approximately seven to fourteen days from now |
| **Later (dated)** | Items beyond the Coming soon period |
| **Recurring** | Approved repeating reminders |
| **Handled** | Completed, declined, or moved items with a short outcome |
| **Migration - Rehome Queue** | Temporary section for the completed version-two conversion; remove it when empty and do not add new entries |

The former **Open - Needs a Date** section is retired. Undated work does not enter Bring-Back.

## the Operations Secretary's Rules

1. During the morning review, add Due today and any useful Coming soon items to Today's Commitments. Do not copy the Later section into Daily.
2. Do not add undated capture, project Next Actions, or vague “follow up sometime” items automatically.
3. Do not use Bring-Back to store project actions that lack a date.
4. When Owner selects a date, add the item under the correct section and link its source project when possible.
5. When an item is handled, move it to Handled with a short outcome. Delete it only when Owner asks.
6. Prevent a permanent overdue list:
   - If Owner does not respond to an item due today, remind him once that day or the next day, then ask whether it needs a new date, belongs in a project, or should be dropped.
   - Advance a `#monthly` item to the next month only after Owner engages with it or explicitly keeps the recurring reminder.
   - Do not allow overdue project work to accumulate in Bring-Back.
7. Move each Migration item into Planned Actions, Next Actions, Waiting For, Calendar, or Handled as appropriate. Remove the Migration section when it is empty.

## Calendar And Bring-Back

| System | Question |
|---|---|
| **Calendar** | When must Owner attend or perform something time-bound? |
| **Bring-Back** | When should Owner reconsider this matter or return his attention to it? |

Use the same date in both places only when both purposes genuinely apply. Prefer one official location.

## Version Two Note

The earlier version accumulated project actions, undated items, and automatically proposed follow-ups. Version two keeps only items with dates Owner selected or approved. Any remaining conversion items belong temporarily in Migration - Rehome Queue until Operations Secretary processes them.
