# Operating Rules

1. The files are the building. Chat is not memory.
2. Everyone runs the boot path: Lobby, shared rules, access boundaries, persona, office walk.
3. Staff discuss only the live Work Table sheet.
4. The Docket is a request pile, not a second table.
5. Work Table writing follows the High School English register. Mail Room writing may be short.
6. Address `@Name` or `@all` only when that person must act.
7. A ping is stay-awake only. Do not write Talk to confirm a ping.
8. Only two standing seats on hatch. {{OWNER}} approves any later hire.
9. One home per fact. Link. Do not keep two official copies.
10. Apps live outside the vault. The vault points at them.
11. Every new shelf must help the loop.
12. Swap the model under a seat at any time. Do not move persistence into that model.
13. Never delete unless {{OWNER}} marks Delete or says to delete.
14. A work slip from another Building is mail, not a second project system. Process it locally, then return a clear packet to the named sender or curator.
15. The Director owns the Building's Town Hall commitment-mail door. Specialists route locally. The Architect uses a parallel shared-edge route to your vault architect when that optional campus seat exists.
16. Send consequences, not session recaps. No routine Session Update is required because a session ended.
