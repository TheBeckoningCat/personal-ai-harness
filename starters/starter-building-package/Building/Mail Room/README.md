## Town Hall and Cross-Building Mail

Town Hall is transit. A central system, another Building, or {{OWNER}} may place a packet there for this Building. Pull the packet into the right local mailbox, confirm the local copy is complete, then clear the transit copy. Nothing stays in Town Hall after a pull.

Packets are mail. They are not unstructured capture and not a second project system.

The Director owns this Building's one Town Hall commitment-mail door. Specialists route findings, recommendations, and Project Candidates to the Director locally. The Architect has a parallel Town Hall route only for shared-edge architecture mail to your vault architect (optional campus seat). No routine Session Update is sent because a session ended.

Do not edit the source ticket, source mailbox, or another Building unless {{OWNER}} explicitly grants access.

## Work Slip Format

A work slip should say enough for the Director to act without reading the sender's mind:

```text
Type: Work Slip
From / to:
Outcome or work requested:
As-of time or deadline, if relevant:
Authorized source work slip / ticket:
Requested return, if not obvious:
```

The Director processes the slip inside this Building. The originating curator stamps the official source ticket. This Building does not keep a second action list for the same outcome.

## Return Mail Format

When work is done, waiting, or blocked, return a short packet to the named sender or curator:

```text
Type: Return / Accepted Commitment / Waiting For / Date / Blocker
Building / Director:
Outcome or decision:
As-of time or deadline, if relevant:
Authorized local source:
Source work slip / ticket, if one exists:
Question or blocker, if any:
```

If Core does not need to decide, do, wait, or remember a date, no mail is required. Local work and session history stay local.

## Project Candidate Format

Use this when local work produced a possible multi-step outcome or accepted commitment and the originating curator has not stamped it yet. A specialist sends it to the Director locally. The Director decides what crosses Town Hall. This is not a work-slip return.

```text
Type: Project Candidate
Building / Director:
Status: Pending candidate / Accepted commitment
Outcome or decision:
{{OWNER}}'s words:
As-of time or deadline, if relevant:
Authorized local source:
Question or blocker, if any:
```

Send one package for a cluster. Keep the owner's language. Mark recommendations as pending, not as {{OWNER}}'s yes. The originating curator stamps the official shape: new project, merge, planned action, recurring practice, someday, reference, or no commitment. This Building does not keep a second action list for the same outcome.

The current canonical packet and instructions live in Town Hall `Mail Room/Packet Kit/Project Candidate.md`. Use [[Town Hall Connection]] for the exact path.

## Architecture Mail

The Architect sends your vault architect only a shared edge another Building or the Campus depends on: canonical address, access, packet field, migration, shared furniture, architecture work-order result, or blocker. Use the same minimum packet fields and add the changed path or requested next action when needed. Ordinary local architecture stays here.
